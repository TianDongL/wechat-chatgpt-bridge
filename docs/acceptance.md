# 发布候选验收

本文区分“代码已实现”“自动化测试已运行”和“真实账号已验收”。只填写实际观察到的结果，不用上一套私人部署的运行记录替代本项目的验收。

## 当前边界

- 版本定位：`0.1.0-alpha.5`，早期发布候选。
- 自动化范围：合成微信协议响应、本机状态与命令行为、浏览器模拟页面。具体通过结果应以当前提交的测试输出或 CI 记录为准。
- 当前本机的具体环境与结果见[候选验证记录](validation.md)。
- **尚未完成：全新配对、真实 ChatGPT 网页账号、干净电脑上的完整往返验收。**
- Windows 是第一支持目标；macOS、Linux 尚未完成真实登录、配对与问答验收。跨平台 CI 通过也不等于对应桌面系统已验证。
- 未验收的能力不得写成“开箱即用”“所有账号可用”或“稳定版”。

## 可重复的自动化检查

在全新检出目录执行：

```sh
npm ci
npm run browser:install
npm test
npm run test:browser
```

记录提交号、系统、Node 版本和结果。测试不得要求生产凭据，不得通过禁用失败用例获得绿色结果。

## 故障验收

在专用测试会话中进行。每次只改变一个条件，并分别检查网页与微信；不要把“没有收到”直接解释成“没有发出”。

| 场景 | 期望行为 |
| --- | --- |
| ChatGPT 登录过期、验证码、限额 | 给出诊断，停止当前投递，不绕过验证 |
| 网页中已有未发送草稿 | 不覆盖草稿，不点击发送 |
| 生成尚未完成 | 不把部分回复作为完整结果回传 |
| 发送点击后断网或进程退出 | 不盲重发，保留不确定状态 |
| 微信响应丢失 | 不因没有收到响应就自动重复发送 |
| 重复微信更新 | 同一条来源消息不再次提交到 ChatGPT |
| 同样的正文分别发送两次 | 按不同来源消息处理，不仅按正文去重 |
| 手工导航或切换网页会话 | 不能把另一段会话的消息误关联到待处理请求 |
| 同一数据目录开两个实例 | 后启动的实例停止，避免并行消费或发送 |
| 其他发送者、群消息、非文字消息 | 不进入 ChatGPT，不改变绑定者 |
| 不确定结果后的新消息 | 原投递记录保留不重发；新消息仍检查网页空闲、会话及草稿，无额外解除命令 |
| 旧版数据升级 | 首页选择要求重新设置；旧暂停状态移除，去重记录保留 |
| HTML 识别与隧道失败 | 普通文字不变，HTML 原文回退发送，不触发额外 GPT 提交 |
| 预览停止与重启 | 本次监听和隧道关闭，旧页面不再提供，原文仍在本机 replies 中 |

## 公开验收记录格式

通过后可新增一个脱敏记录，包括：日期、提交号、操作系统、Node/Chromium 版本、检查项、观察结果、仍未覆盖的场景。截图只展示合成测试文字；隐藏二维码、账号、会话 ID 和浏览器个人信息。

不要在记录中附数据目录、登录响应、请求头、抓包文件或真实聊天历史。一次账号验收只支持该账号、版本和环境的结论，不应外推为全平台保证。
