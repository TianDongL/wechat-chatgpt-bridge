# WeChat ChatGPT Bridge

在微信里继续你的 **ChatGPT 网页会话**。电脑上的可见浏览器负责打开 ChatGPT，微信负责收发文字。

[English](README.en.md) · [功能对齐清单](docs/feature-parity.md) · [架构](docs/architecture.md) · [验证记录](docs/validation.md) · [验收清单](docs/acceptance.md) · [安全说明](SECURITY.md)

**当前版本：`0.1.0-alpha.6` 发布候选。** 第一版面向愿意反馈问题的早期使用者。自动化测试不能代替真实账号验收；当前尚未完成全新账号、干净电脑上的微信 ↔ ChatGPT 端到端验收，请先看[已验证范围与待验证项](docs/acceptance.md)。

## 它能做什么

- 将扫码绑定者发来的微信单聊文字送入选定的 ChatGPT 网页会话，再把完成的文字回复发回微信。
- 通过 `/list`、`/cd`、`/where` 管理已有会话，发送 `/help` 查看命令。
- 使用专用浏览器目录保存登录状态，无需复制 Cookie、填写 OpenAI API Key 或安装 Codex。
- 普通回复文字原样发送；遇到完整 HTML 组件时，只把组件替换成手机可打开的网页链接，保留周围文字与完整原文。
- 只把完整单行消息识别为命令。长段落、代码块中出现 `/cd` 不会切换会话。
- 保存投递状态。结果无法确认的消息会留下记录，不自动重复提交；新消息仍检查页面是否就绪。

第一版接收文字消息，支持 HTML 源码组件预览、本机主动通知，以及可选 Windows 本机模式的 Dot 主动提醒。不支持群聊、其他联系人、图片/语音消息或附件；桥自身不创建定时任务。依赖 ChatGPT 原网页环境的专用组件可能无法完整还原。电脑、终端和所选接入程序需要保持运行。

这是独立社区项目，与 OpenAI、Tencent 无隶属关系。微信侧参考 Tencent 的 [iLink Bot 协议](https://github.com/Tencent/openclaw-weixin/blob/main/docs/protocol.md)；ChatGPT 侧通过 Playwright 操作可见网页。**网页自动化不是官方 ChatGPT API，页面变化、登录验证或账号限制都可能使接入暂时不可用。**

## 开始前

| 需要 | 说明 |
| --- | --- |
| Node.js | 22.13 或更新版本，推荐受支持的 LTS 版本；包含 npm |
| 电脑 | 第一版优先面向 Windows。macOS、Linux 尚无真实账号验收记录 |
| ChatGPT | 能在本机浏览器正常登录并聊天的账号 |
| 微信 | 能完成 iLink Bot 扫码绑定的微信账号；服务可用性取决于微信侧 |
| 网络 | 本机能访问 ChatGPT、微信 iLink 服务，以及首次安装所需的 npm 和 Playwright 下载服务 |

如果本机浏览器本身无法打开 ChatGPT，先解决访问问题。本项目不会绕过登录验证、验证码或平台访问限制。

## 快速开始

下载[源代码 ZIP](https://github.com/TianDongL/wechat-chatgpt-bridge/archive/refs/heads/main.zip) 并解压，或克隆仓库，然后在项目目录打开终端：

```sh
git clone https://github.com/TianDongL/wechat-chatgpt-bridge.git
cd wechat-chatgpt-bridge
```

Windows 用户装好 Node.js 后，也可以双击 `setup.cmd` 完成安装与首次设置，之后双击 `start.cmd` 启动。下面是各平台的终端方式：

```sh
npm ci
npm run browser:install
npm run setup
```

首次设置时：

程序会自动下载固定版本的官方 cloudflared 并校验 SHA-256，供 HTML 临时网页使用；不需要 Cloudflare 账号、域名、服务器或手动开启浏览器调试。下载失败仍可继续设置普通文字聊天，恢复网络后重新运行 `npm run setup` 重试。支持的预览程序平台为 Windows x64、Linux x64/arm64、macOS x64/arm64；其他平台仍可使用文字模式。

1. 在桥接程序打开的专用浏览器中登录 ChatGPT。登录和验证码都由你本人完成。
2. 打开一个已有的普通 ChatGPT 会话。若账号还没有会话，先在网页手动聊一句，等地址变为 `https://chatgpt.com/c/…`。确认页面已加载、输入框为空且没有正在生成的回答，然后回到终端按回车。桥只接入已有会话。
3. 用手机微信扫描终端显示的二维码并确认绑定。若出现校验码提示，按终端说明输入。不要把二维码或登录结果发到 Issue 中，也不要让两套桥同时使用同一个机器人。
4. 设置结束后启动桥：

```sh
npm start
```

等终端显示桥运行中，再从微信向刚刚绑定的机器人发送：

```text
/help
```

收到命令说明后，再发送一条容易核对的测试消息，例如：

```text
请只回复：连接成功
```

**首次连接成功的标准：** 微信收到命令说明；电脑的 ChatGPT 页面出现你发送的这条测试消息；页面生成完成后，微信收到对应回复。只看终端显示启动成功，还不能确认整条链路已经可用。

桥接期间请勿在同一个专用浏览器标签里手动发送消息、切换会话或保留未发送草稿。程序会对部分冲突停止投递，避免覆盖草稿或拿错回复。

停止时在运行桥的终端按 **Ctrl+C**。再次使用时，在项目目录执行 `npm start`。启动前尚未被桥接收的历史消息不会补发；程序退出前已经保存的待处理消息会按记录恢复。Windows 的 `npm start` / `start.cmd` 会在本机用系统 .NET Framework 编译器准备一个小型进程宿主：关闭终端或宿主后，一并清理本次桥、浏览器与隧道；它不重启失败的消息，也不安装服务或开机自启。请使用上述启动入口，而非绕过宿主直接运行内部 CLI。

## 从早期候选升级

停止旧版后更新代码并执行 `npm ci`，保留原数据目录。若旧版使用已有 Chrome 接入，请运行 `npm run browser:install` 和 `npm run setup`，在专用浏览器重新登录并选定已有会话；可继续使用原微信配对。两种接入模式都无需手动开启浏览器远程调试。旧版首页选择需要重新设置，旧的待确认记录仍保留且不会重发。

从 `alpha.2` 升级也请运行一次 `npm run setup`，自动准备 HTML 预览程序；已有网页登录和微信配对可以继续使用。

## 可选：本机 Codex / Dot 接入

如果需要账号最近会话列表、原始回复接口、`/cd dot`，以及切到 GPT 后仍收到 Dot 主动提醒，可在 Windows 上使用：

```sh
npm ci
npm run setup:native
npm start
```

保持本机 Codex 应用运行并登录目标 ChatGPT 账号；本机需要已有 Codex 工作对话供接口建立调用上下文。设置时粘贴同一账号的已有 GPT 网页会话链接，再选择是否启用发现的个人 Dot，最后扫码或复用自己的微信配对。无需安装桥的浏览器、复制 Cookie、填写 API Key 或开启 debug。普通 `npm run setup` 可切回网页模式。

本机模式读取当前安装的 Codex 登录会话，凭据只在内存中使用；从本机会话索引读取少量元数据以建立调用上下文，不读取 Codex 对话正文。Dot 必须通过当前账号、个人房间与两个成员身份的验证。公开仓库没有预置维护者的账号或房间。**此模式依赖非公开的本机与网页接口，可能随平台升级变化；没有 Dot 的账号仍可只接 GPT。** 单次输入上限为 4096 UTF-8 字节；更长内容请分段。

普通文字只发给当前 `/where` 所示入口。Dot 已启用时，主动提醒始终单独监听并以 `【Dot】` 前缀回传；切换到 GPT 不会关闭它。电脑和 Codex 必须保持在线。

从 `alpha.6` 起，本机模式自动使用 WebSocket 接收所选网页会话的完成通知，再读取对应的最终回复。连接正常且没有待处理消息时，不再持续读取整段历史；在两个 GPT 会话间切换复用同一连接，回到 Dot 时关闭网页连接。断线会退避重连并补读，等待回复时仍保留低频检查。它减少了重复请求，但不能保证不出现 429，收到限流后仍遵守服务端的等待时间。普通网页登录模式继续通过可见页面收发。

## 本机通知、状态与停止

桥运行时，可在另一个终端执行 `npm run status` 查看脱敏状态，或 `npm run stop` 停止本次桥。本机自动化程序还可以把通知 JSON 通过标准输入交给：

```sh
node src/cli.js notify --stdin
```

输入格式为 `{"request_id":"my-task-unique-id","purpose":"reminder","text":"通知正文"}`，随后关闭标准输入。`purpose` 支持 `reminder`、`progress`、`todo`、`test`。同一个请求 ID 不重复投递；正文不能指定收件人。程序只发送给扫码绑定者，要求先收到过当前微信登录下的本人消息，以建立回复上下文；平台拒绝或超时不能当作未发送而重试。不自行假设微信上下文的有效时长或每日配额。

控制接口只绑定本机回环地址，使用私有目录中的随机令牌；它与 HTML 预览分开，不经公网隧道暴露。通知程序只返回状态，不打印令牌和正文。

## HTML 组件如何显示

转发层保持收到的普通文字、空行、Markdown、行内代码和非 HTML 代码块原样。本机模式直接读取最终回复源文本；新版网页模式优先使用页面“复制”动作给出的源文本，在内存捕获该动作，不读取或改写系统剪贴板。若网页不能导出原文，则按可见内容恢复 Markdown，格式可能与原始源码不同。完整的 HTML 文档、片段、HTML 代码块或可识别组件会被替换为“HTML 组件，点击查看”的链接。只替换组件范围，不改写前后的文字；多个组件分别链接到同一预览页的对应位置。

页面显示原文字和可交互组件，并提供“查看原始回复”和原文下载。原始完整回复仍保存在本机 `replies` 目录。只有已提取到的 HTML 源码可以预览，不能保证导出所有 ChatGPT 专用组件；预览页保留原会话入口。

采用本机内存网页配合 [Cloudflare Quick Tunnel](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/) 的方式。**链接持有者可以查看该条完整回复，内容会经 Cloudflare 传输，请勿随意转发。** 普通文字聊天无需隧道；预览链接在电脑离线、桥停止/重启或旧页面被容量限制淘汰后不可用。当前最多保留 128 页、总计 32 MiB。临时隧道没有可用性保证，不适合作为永久托管。

HTML 代码在隔离框架中执行，尽量保留原 CSS 和 JavaScript；访问父页面、外部接口、表单提交和嵌套网页会受限制。预览失败、未准备好或组件不完整时，直接发送原文，不丢弃回复，也不重新请求 GPT。

## 微信命令

命令必须独占一条单行消息；前后空格可以省略。正斜杠 `/` 和反斜杠 `\` 均可使用。

切换命令以 `/cd` 为主，旧的 `/switch` 仍作为兼容别名。列表、当前会话和切换结果都会提示发送 `/help` 查看命令。

| 命令 | 用途 |
| --- | --- |
| `/help` | 查看帮助 |
| `/where` | 查看当前入口、会话标题和未确认结果数量 |
| `/list` | 列出当前页面侧栏可见的最多 12 个会话，并给出本次编号 |
| `/cd 1` | 切换到最近一次 `/list` 中的第 1 个会话 |
| `/cd https://chatgpt.com/c/<会话UUID>` | 按普通 ChatGPT 会话链接切换 |
| `/cd <会话UUID>` | 按会话 ID 切换 |
| `/cd gpt` | 回到 setup 绑定的默认 GPT 会话 |
| `/cd dot` | 可选本机模式：回到已绑定的个人 Dot |

默认网页模式的 `/list` 展示侧栏当时可见的会话，可选本机模式读取账号最近 12 个会话。编号保存在本机，重启后仍对应上次成功返回的列表。`/cd 1` 直接选中该列表的第一项。网页限流时，后续正文按顺序等待所选会话恢复，最多等待 10 分钟。首次使用先成功获取一次 `/list`。这里使用 ChatGPT 网页地址中的会话 ID。

在网页里改名后，再发一次 `/list`。列表中包含当前会话时，`/where` 和再次 `/cd` 的回执也会使用新标题，当前轮次和读取位置继续保留。

已绑定个人 Dot 时，网页的完整回复送达微信后开始计时。连续 10 分钟没有新的微信输入，桥会切回原 Dot 并发一条微信提醒。发送命令会重新计时，发送正文会等新一轮回复送达后再计时。Dot 的主动提醒会继续转发。

下面整条消息会原样作为普通文字发送给 ChatGPT，不会切换：

```text
帮我解释这个命令：
/cd 1
它为什么会切换会话？
```

如果网页提交或回答出现“不确定”，请先查看网页和微信，判断原消息、回复是否已经出现。桥会保留这条消息的投递记录，不自动重发，也不要求输入额外的解除命令。后续新消息仍须通过会话、登录、空闲和草稿检查。明确尚未提交的忙碌/暂不可用消息最多排队 10 分钟，按顺序恢复；已经尝试提交的消息不会因此重发。本机模式在提交回执不清楚时最多做 90 秒只读确认。等待网页回复时不能切换入口，但帮助与 Dot 提醒仍可处理。微信回传失败或无法确认时，完整回复保存在本机数据目录的 `replies` 子目录，不自动重新回传。不要在尚未确认时手动重复发同一条消息。发送前或发送后的断网，都可能让客户端无法判断服务端是否已经接受；本项目不承诺网络故障下的“恰好一次”交付。

## 诊断与常见问题

本机模式的 `npm run status` 还会显示 `webPush` 连接状态、`webHistoryReads` 历史读取次数和 `webRetryInSeconds` 限流剩余等待时间。切回 Dot 后，网页连接状态为 `off`；这些计数不含消息正文和会话 ID。

```sh
npm run doctor
```

运行诊断前，先用 Ctrl+C 停止正在运行的桥。诊断会检查本机安装、配对文件和待确认状态，并打开专用浏览器检查页面；它不发送消息，也不验证微信服务端登录仍然有效。它不等于已经完成一次真实问答。提交反馈时，只附必要的错误提示、操作步骤与脱敏截图，勿附整个数据目录。

| 现象 | 处理 |
| --- | --- |
| 提示找不到 Chromium | 在项目目录运行 `npm run browser:install` |
| 出现登录页、验证码或页面没有输入框 | 在专用浏览器中手动完成登录或验证；确认能正常聊天后重新启动 |
| 提示输入框已有草稿 | 在专用浏览器中自行处理草稿，再继续；桥不会替你覆盖 |
| `/list` 缺少某段历史 | 手动复制普通 ChatGPT 会话链接，用 `/cd <链接>` 切换 |
| 扫码过期、绑定中断 | 重新运行 `npm run setup`，使用新二维码；不要复用截图中的旧二维码 |
| 微信登录已过期 | 停止桥后重新运行 `npm run setup`，在已有配对提示中输入 `relogin`；保留原数据目录和账本 |
| 微信回传被拒绝 | 先在微信给机器人发一条新消息，刷新回复上下文；若仍失败，保留脱敏错误码反馈。限制以微信服务实际响应为准 |
| “提交结果不确定”或回复超时 | 查看当前网页，避免重复发送原消息；等网页空闲、输入框为空后可发送新消息 |
| 另一个实例正在使用数据目录 | 先停止原终端里的桥；同一数据目录同时只运行一个实例。若旧进程已经退出但锁残留，运行 `npm run unlock`；它只会清除进程已不存在的运行锁 |
| 页面更新后不再工作 | 保留错误码并反馈；不要通过反复点击发送或重跑来猜测是否成功 |
| HTML 仍显示为源码 | 检查终端的预览状态；未安装时重新运行 `npm run setup`。隧道不可用或未识别为完整组件时会保留原文 |
| 旧预览链接打不开 | 电脑须在线且桥正在运行；重启或容量淘汰会使旧页失效，可到 GPT 原会话或本机 `replies` 查看原文 |

## 数据保存在什么地方

默认数据目录是当前用户主目录下的 `.wechat-chatgpt-bridge`，与源代码分开。它包含微信登录凭据、专用浏览器登录状态、投递记录及本机回复文件；待处理状态中可能保存消息正文。回复文件保存在 `replies` 子目录，便于微信回传失败时查找。这些文件涉及聊天隐私，部分文件还可能让他人使用你的登录身份，**不要上传、共享或打包进发行版**。Playwright 也明确要求保护[持久化登录状态](https://playwright.dev/docs/auth)。

可以指定独立目录。首次使用应选择新的或空的目录，不能将现有项目目录或用户主目录当作数据目录；后续命令必须使用同一个目录：

```sh
npm run setup -- --data-dir ../wechat-chatgpt-data
npm start -- --data-dir ../wechat-chatgpt-data
npm run doctor -- --data-dir ../wechat-chatgpt-data
```

`unlock` 也支持相同的 `--data-dir` 参数。推荐将自定义目录放在仓库外。若使用仓库内路径，请检查 `.gitignore`，不要认为任意自定义路径都会自动被忽略。删除数据目录会丢失登录状态和去重记录；运行中不要删除，也不要靠删除它来解决发送结果不确定的问题。更多细节见 [SECURITY.md](SECURITY.md)。
